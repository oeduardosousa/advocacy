# Advocacy Portfolio — Project Rules

Stack (approved, details in BRIEF.md): Next.js (App Router, static export) + TypeScript + Tailwind CSS + MDX content in repo. Motion: GSAP + ScrollTrigger + Lenis. No database, no payments.

- Use the approved stack documented in BRIEF.md; do not add services without approval.
- Commit each completed, verified step with a clear message.
- Never push, force-push, or commit .env files or secrets.
- `.env*` stays in .gitignore (only `.env.example` allowed) before any commit.
- Use emil-design-eng for animations and interactions.
- Use Impeccable for design and UI audits.
- Never expose secrets in code, logs, browser bundles, or chat.
- Test changes before committing; get approval before production changes.
- Do not invent firm data, testimonials, results or legal claims; mark placeholders clearly as demo content.
- Respect OAB advertising rules in copy (no promises of results, no solicitation tone).
- Respect prefers-reduced-motion; all motion must have a static fallback.
- Language: pt-BR for all site copy; code and docs in English.
- Workflow order: DESIGN.md (after research approval) -> landing page -> inner pages -> review.
